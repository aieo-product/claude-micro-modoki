Claude Approval Console × Codex Micro

Claude Code の承認操作とエージェント状態表示を Codex Micro（Work Louder 製マクロパッド）の物理キーと LED に移設する。verylowfreq/m5stack_claudecode_approval_console（MIT）を fork し、デバイス層を HID に差し替える改修の設計書。

UPSTREAM verylowfreq (MIT) REPO aieo-product/claude-micro-modoki TARGET Codex Micro (kbd-1.0)

01概要と目的

Claude Code はシェル実行やファイル編集の前に承認を求める。元プロジェクトはこの承認を M5Stack Core2 の画面とボタンに移した。本改修では同じ hooks 基盤を維持したまま、出力先を Codex Micro の RGB LED、入力元を Codex Micro の物理キーに置き換える。あわせて Notification / Stop フックを追加し、Codex 純正の「Agent Keys」相当のセッション状態表示を Claude Code で実現する。

  • ゴール1: PreToolUse の承認（allow / ask / deny）を Codex Micro のキー押下で返す
  • ゴール2: セッション状態（待機・実行中・入力待ち・完了）を LED 色で常時表示する
  • ゴール3: 複数 Claude Code セッションをキー単位で識別・切り替えできる
  • 非ゴール: Codex アプリ純正統合の複製、Claude Desktop（GUI 版）の操作

02システム構成

現行（upstream）

Claude Code --PreToolUse hook--> hook_client.py --HTTP :35703--> bridge.py --WebSocket :35704--> M5Stack Core2

改修後（本設計）

Claude Code --PreToolUse / Notification / Stop--> hook_client.py
      --HTTP 127.0.0.1:35703--> bridge デーモン
          ├─ SessionRegistry（session_id → キー番号の割当）
          ├─ DeviceAdapter IF
          │    ├─ HidAdapter（Codex Micro / raw HID・本命）
          │    └─ WsAdapter（M5Stack 互換・upstream 追従用に温存）
          └─ --raw HID--> Codex Micro（LED 書き込み / キーイベント購読）

デバイス層をアダプタとして抽象化することで、upstream の M5Stack 対応を壊さずに Codex Micro 対応を追加でき、将来の upstream 取り込みも容易になる。

03コンポーネント設計

hook_client.py（軽微改修）

stdin の hook JSON を bridge へ POST し、応答を hookSpecificOutput.permissionDecision に変換して返す。改修点: イベント種別（PreToolUse / Notification / Stop）の透過、session_id の付与、ログの肥大化対策（ローテーション）。timeout・不明応答は現行どおり deny にフェイルクローズ。

bridge デーモン（再実装）

現行はグローバル変数 + busy-wait の単一リクエスト前提。asyncio ベースに書き直し、リクエストID付きキュー、同時複数セッション、応答タイムアウト、systemd / launchd 常駐化に対応する。

HidAdapter（新規）

hidapi（Python）で Codex Micro の raw HID インターフェースを開き、(a) LED 状態の書き込み、(b) キー押下イベントの購読を行う。QMK raw HID（usage page 0xFF60）を想定。VIA プロトコル互換かは Phase 0 で実機検証。

SessionRegistry（新規）

Claude Code の session_id と Agent Key（キー1〜6）を対応付ける。SessionStart で空きキーを割当、Stop / SessionEnd で解放。承認要求はそのセッションのキーを PENDING 色に点滅させる。

04プロトコル定義

hook_client → bridge（HTTP POST /decision）

{ "event": "PreToolUse", "session_id": "…", "cwd": "…",
  "tool_name": "Bash", "tool_input": { "command": "npm test" } }

bridge → hook_client（応答）

{ "result": "accept" | "fallback" | "deny" | "timeout" }
// accept→allow / fallback→ask / deny・timeout・不明→deny（フェイルクローズ）

bridge ⇄ Codex Micro（raw HID 64byte レポート・案）

方向コマンドペイロード
PC → 鍵盤0x01 SET_LEDkey_index(1) + state(1: idle/pending/allow/hold/deny)
PC → 鍵盤0x02 CLEAR_ALL—
鍵盤 → PC0x81 KEY_EVENTkey_index(1) + action(1: tap/double/long)

純正ファームで raw HID が開放されていない場合は、Phase 4 で QMK 自前ビルドに切り替える（Work Louder のボード定義は QMK 本体にマージ済み）。

05LED / キー割当仕様

状態色意味 / 遷移
IDLE青（微灯）セッション割当済・待機中
PENDING黄（点滅）PreToolUse 承認待ち。キー tap = allow、long = deny、double = ask（画面で判断）
ALLOW緑（1.5s）承認直後のフィードバック → IDLE へ
HOLD紫（1.5s）ask（手動確認へフォールバック）
DENY赤（1.5s）拒否・タイムアウト → IDLE へ

色と点滅時間は upstream ファームウェア（colorForState() / RESULT_FLASH_MS=1500 / BLINK_INTERVAL_MS=400）の値を踏襲し、M5Stack 版と体験を揃える。承認タイムアウトは 240 秒（upstream 準拠）。

06セキュリティ方針

upstream の README は「ポート一致の通信を無条件に信頼する」既知の弱点を明記している。本改修では以下を必須とする。

  • HTTP は 127.0.0.1 バインドに固定（現行は 0.0.0.0）。HID 接続は USB 直結のためネットワーク露出なし
  • hook_client ⇄ bridge 間に共有トークン（環境変数 APPROVAL_BRIDGE_TOKEN）を導入
  • WsAdapter を使う場合のみ 35704 を開放し、接続時トークン検証を追加
  • ログに tool_input の全文を残さない（コマンドは先頭 200 字で切り詰め）
